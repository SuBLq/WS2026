# Whiteout Survival — справочник SuBL

Статический мобильный сайт для GitHub Pages. Готовые страницы находятся в корне,
`guides/` и `tools/`. Никакой сервер приложения или установка npm-пакетов не нужны.

## Редактирование

- `content/guides/…` — содержимое гайдов без общей оболочки.
- `content/tools/…` — разметка калькуляторов.
- `content/pages.json` — названия, описания, категории и зависимости страниц.
- `content/catalog.json` — порядок материалов на главной.
- `templates/` — общая шапка, нижнее меню, поиск, HTML-документ и service worker.
- `assets/css/shell.css` — общая оболочка и доступность.
- `assets/css/content.css` — чтение, таблицы и общие блоки гайдов.
- `assets/css/interface.css` — главная и единый внешний вид.
- `assets/css/pages/` — специфические схемы и компоненты отдельных гайдов.
- `assets/js/` — тема, поиск, избранное, таблицы, офлайн-режим и общие действия.
- `tools/research/` — данные и логика калькулятора исследований.
- `assets/js/construction-data.js` — исходные данные строительства.
- `assets/js/tools-construction-index.js` — интерфейс строительного калькулятора.

Публичные HTML-файлы генерируются: правки в них будут перезаписаны сборкой.
Для изменений текста редактируйте соответствующий файл в `content/`.

## Сборка и проверки

Нужен Python 3.10+ для сборки и Node.js 18+ для проверки логики. Зависимостей нет.

```text
python scripts/build.py
python scripts/check_site.py
node scripts/test_logic.cjs
```

Сборка создаёт все страницы, поисковый индекс и версии ресурсов по их содержимому.
Проверка контролирует локальные ссылки, якоря, изображения, размеры и версии файлов.
Проверка логики покрывает поиск, бонусы, стоимость и зависимости исследований,
разделение версий кэша, ограничение области worker и ошибки офлайн-загрузки.

Для локального просмотра:

```text
python -m http.server 8765 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8765/`. Офлайн-режим работает через HTTP localhost/HTTPS,
а не при открытии HTML как локального файла.

## Изображения

Оригиналы сохранены для совместимости ссылок и полноэкранного просмотра.
Варианты для отображения описаны в `content/image-variants.json`; размеры —
в `content/image-sizes.json`. Обычная сборка использует эти файлы без Pillow.

После добавления или замены изображений обновите варианты и размеры:

```text
python scripts/optimize_images.py
python scripts/build.py
```

Только для подготовки изображений требуется Pillow. Варианты WebP сохраняются
рядом с оригиналами. Размеры `width`/`height` и `srcset` добавляются сборкой.

## Офлайн и пользовательские данные

Тема, избранное, недавние материалы и профили калькуляторов хранятся на устройстве.
Существующие ключи профилей сохранены; миграция старых профилей калькуляторов остаётся.

Service worker предварительно сохраняет небольшую оболочку. Посещённые ресурсы
попадают в ограниченный кэш. «Офлайн» в статье загружает сам гайд, оформление,
поиск, изображения и их адаптивные варианты в отдельный постоянный кэш.
Успех отображается только после загрузки всех ресурсов.

Новая версия worker ждёт нажатия «Обновить». Уже скачанные гайды сохраняются
при обновлении оболочки. Непосещённая страница без соединения показывает понятное
сообщение вместо перенаправления на главную под неверным адресом.

## Публикация

Перед загрузкой в существующий репозиторий выполните сборку и обе проверки.
Публикуйте готовый корень этого проекта обычным способом GitHub Pages.
Относительные ссылки рассчитаны и на сайт в подпапке репозитория.

В рабочей копии нет `.git` и настроек действующего репозитория: текущие изменения
не отправлены в GitHub и не опубликованы автоматически.
